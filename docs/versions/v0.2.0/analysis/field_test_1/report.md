대상: `data/landmark_sequences/`의 로그 13개(원본은 읽기만 했고 수정하지 않았다). 카메라는 실행하지 않았다. Phase 2 구현은 하지 않았다.

**이 분석의 한계(먼저 읽을 것)**: 한 사람, 한 카메라 배치, 하루의 데이터다. 세션당 반복이 5~10회라 모든 임계값은 확정이 아니라 **초기값 제안**이다.
세션 0(시험)은 임계값 산출에 쓰지 않았다(세션 0을 쓴 곳은 7장의 jump 비율 재확인과 9장의 BodyLock 확인뿐이며, 둘 다 지시받은 용도다).

- 세션 6은 5회로 실제와 같지만 우연이다. 첫 반복(21.7~24.5초)은 올라온 뒤 `stand`가 안 나와 두 번째 반복이 시작하는 27.0초에 늦게 세어졌다.
- 비스쿼트 오카운트(8b 2, 8c 1): 앉기 구간에 `squat` 라벨이 3~4프레임 나오거나(8b), 런지에서 `squat`/`walk`가 섞여(8c) 상태기계가 진행됐다.

### depth (최저 무릎각)
- 세션 1, 2(정상) 최악 70.9° vs 세션 3(얕음) 최선 86.4° → 완전 분리(AUC 1.00). 정확도 최대 경계 78.7°(깨끗한 음성 세션 1, 2, 5, 9 기준 80.1°).
- **제안**: 정상 ≤ 80°, 주의 80~95°, 교정 > 95°. 정상 상한은 두 분포 사이의 틈(70.9~86.4°)에 있다. **교정 하한(95°)은 근거가 약하다**: 의도한 오류가 한 수준(세션 3)뿐이어서, 세션 3 중앙값(91°)과 최대(102°) 사이에 둔 가정이다. 이 선으로 세션 3은 주의 5, 교정 3이 된다.
- **세션 2(깊게)는 감점되지 않는다**: 8/8 정상(깊이는 상한만 판정). 세션 1, 5, 9도 전부 정상.
- 주의: 세션 4(상체 숙임)는 깊이도 얕아져 8개 중 7개가 depth "주의"가 된다(77.9~90.5°). 상체 숙임과 얕은 깊이가 같이 일어난 것이다. 보조 지표(엉덩이 y−무릎 y)는 분리가 덜하고(세션 3 대 깨끗한 음성 AUC 0.98), 평행 스쿼트(세션 1)조차 엉덩이가 무릎보다 위로 나온다(−0.08~−0.02). 보조로만 기록한다.

### torso_shin (|몸통각 − 정강이각|, 최저점)
- 세션 1, 2 최악 18.8° vs 세션 4 최선 31.2° → 분리(AUC 1.00). 정확도 최대 경계 25.0°(세션 3 포함 깨끗한 음성 기준 30.8°, AUC 0.997).
- **제안**: 정상 ≤ 25°, 주의 25~35°, 교정 > 35°. 적용 결과: 세션 1, 2, 5, 9는 전부 정상(32/32). 세션 4는 교정 7, 주의 1.

## 7. ML 배제 조건과 stretch (`ml_label_share_by_phase.csv`, `ml_exclusion_variants.csv`, `ml_labels_when_knee_below_150.csv`, `plots/ml_label_share_by_phase.png`)

**jump 재확인**: 세션 0에서 무릎각 150° 미만 구간(14.5초)의 라벨은 squat 70.8%, jump 21.2%였다(지시의 "약 20%"와 일치). 같은 기준으로 정상 세션 1~5, 9에서도 jump 비율은 2~27%다(1: 17%, 2: 15%, 3: 27%, 4: 2%, 5: 10%, 9: 7%).

**정상 스쿼트 반복(세션 1~5, 9, 48회)의 구간별 라벨 시간 비율**

| 라벨 | 하강 | 최저점 | 상승 |
|---|---|---|---|
| squat | 24% | 97% | 47% |
| bendover | 50% | 3% | 25% |
| **jump** | **17%** | 0.3% | **22%** |
| run | 5% | 0% | 3% |
| walk | 3% | 0% | 2% |
| stand | 2% | 0% | 1% |
| lying | 0.3% | 0% | 0% |

사선·정면 세션에서는 하강·상승에 `sit`/`run`/`stand`가 섞인다(정면: sit 하강 22%, 상승 17%).

**제안**
1. **`jump`는 배제 목록에서 뺀다.** 정상 스쿼트 반복의 jump 비율이 0~42%(세션 3 최대 42%)이고 하강 17%, 상승 22%를 차지한다. 목록에 넣으면 정상 반복이 Y 근처에서 탈락한다. 비스쿼트에서 jump가 하는 일도 없다(걷기 0%, 런지 0%, 의자는 하강 29%지만 의자는 ML로 잡지 않는다).
2. 배제 목록은 **`walk, run, lying`**, **Y = 0.40**(초기값). 정상 최대 0.280(세션 9), 비스쿼트 최소 0.492(런지). 틈의 중앙은 0.386. `jump`를 넣은 기존 목록이면 정상 최대 0.424(세션 3) vs 런지 0.492로 틈이 0.07밖에 없다(권장 안의 틈은 0.21).
   - `run`과 `lying`은 이 실측에서 비스쿼트 배제에 쓰인 적이 없다(걷기 8a는 전부 walk). 달리기·눕기 같은 동작은 이번 데이터에 없으므로 **검증하지 못한 채 안전을 위해 유지**하는 것이다. 세션 9에서는 `run`이 정상 서 있는 자세에 붙어서 (walk+run+lying 기준) 반복의 13~28%를 차지하므로, 방향이 바뀐 정상 스쿼트에서 비율이 높게 나올 수 있다는 점을 알고 Y를 정해야 한다.
3. **`stretch`는 배제 목록에 넣지 않는다.** 정상 반복 48회 모두 stretch 0%이고, 런지 스트레칭(8c)도 `walk`/`squat`로 분류돼 stretch 라벨이 0%다. 넣어도 걸러지는 것이 없고 정상 반복도 손해 보지 않아 **데이터로는 결정 근거가 없다**. 스트레칭 자세에서 스쿼트하는 경우를 대비한 판단은 사용자 몫이다. 런지는 기하 조건(양발 간격)이 훨씬 확실하다.
4. `sit`/`bendover`는 이전 결정대로 제외 목록에 없다. 정면 세션에서 `sit`가 하강·상승의 17~22%를 차지해 넣으면 정상 정면 스쿼트가 걸린다.

**ML 조건과 기하 조건 비교**
| | 기하(길이, 양발 간격, 몸통) | ML(walk+run+lying) |
|---|---|---|
| 가장 좁은 틈 | 몸통: 정상 최소 39.3° vs 비스쿼트 최대 20.5°(1.9배). 양발 간격 0.05 vs 0.55 | 정상 최대 0.28 vs 비스쿼트 최소 0.49 (1.75배) |
| 방향·시점 | 양발 간격은 측면 전용. 길이는 시점과 무관 | 방향(세션 9)·시점(6, 7)에서 라벨이 바뀜(`run`이 서 있는 자세에 붙음). v0.1.x가 틀린 이유와 같다 |
| 의자 | 몸통 젖힘으로 잡힘 | 못 잡음(0.0~0.12) |
- **결론**: 반복 확정의 기본 수단은 **기하 조건**이 더 안정적이다(틈이 더 넓고 라벨 분류 오류에 영향받지 않는다). 다만 양발 간격은 측면에서만 쓸 수 있으므로, **ML 조건은 측면이 아닌 시점과 이번에 보지 못한 동작(달리기·눕기)을 위한 2차 방어선**으로 `jump`를 뺀 목록 + Y 0.40으로 유지하는 것을 권한다.

- 극단값: 측면 프레임에도 한두 프레임 (a) 0.392, (b) 25.8° 같은 튀는 값이 있다. 한 프레임 판정에 의존하지 말고 연속성(9장)을 둬야 한다.
- **반복 시작 시점(STANDING에서 잠긴 값) 판정**: 측면 세션은 반복 48/48회 모두 측면으로 잠겼다. 사선(6) 0/5, 정면(7) 0/5는 측면 아님으로 잠겼다(올바름).
- **세션 7에서 BodyLock은 잡혔다.** 세션 7은 전체 프레임의 87.1%(서 있는 프레임은 100%)가 `locked`이고, 그중 `view_is_side`는 0%다. 임시 정책이 시점과 무관하게 서 있고 전신이 유효하면 잠그기 때문이다. `BodyLock.quality_enabled()`는 `view.is_side`를 같이 보므로 품질 판정은 꺼지지만, "정면에서는 잠금 자체가 잡히면 안 된다"는 조건은 **지켜지지 않았다**. Phase 2에서는 측면 판정이 유지될 때만 획득해야 한다(9장).

## 9. 세션 0: 정면으로 돌아섰을 때 BodyLock이 풀리지 않은 원인과 설계 제안 (`lock_release_evidence_*.csv`, `session0_nonside_standing_episodes.csv`, `plots/session0_turn_lock.png`)

**로그로 확인한 원인**
- 29~31초: 서 있는 상태에서 (a)가 0.04 → 0.59로 올라가고 (b)가 89° → 29°로 내려가 **28.8~29.5초(12프레임, 0.67초) 비측면**이 이어졌다. 그 사이 `locked`는 계속 True(12/12프레임), `released_missing` 이벤트는 0이다. 잠금의 `view_is_side`만 False로 기록됐다.
- 73~76초: **74.1~76.5초(40프레임, 2.35초) 비측면**. 이 사이 `locked`는 100%이고, **잠금의 다리·방향이 7번 바뀌었다**(`changed` 이벤트, 74.4~75.4초: left/right → left/left → left/right → right/left → right/right → right/left → left/right).
- 원인은 `GeometryTracker.update()`의 구조다.
  1. 해제 경로가 `update_missing()`(사람·Pose를 2초 이상 놓침) 하나뿐이다. 돌아선 동안은 사람이 계속 검출돼서 풀릴 일이 없다.
  2. 서 있고(평활 무릎각 ≥ 160°) 전신이 유효하고 facing이 정해지는 프레임이면 **프레임마다 해제 후 다시 잠근다**(`release()` 뒤 `acquire(geometry_now)`). 시점은 조건이 아니므로 정면 프레임의 값으로 갱신된다. 정면에서는 발끝 방향(heel→foot_index)이 불안정해 다리와 방향이 프레임마다 뒤집힌다.
  3. 그래서 로그의 `lock.locked`는 True이고 `lock.view_is_side`는 False인 상태(잠겼지만 측면 아님)가 된다.

**Phase 2 설계 제안 (STANDING 중 시점 감시)** — 초기값, 확정 아님
- **획득**: STANDING이고 전신 유효이고 facing이 정해지고 **측면 판정이 0.5초 연속** 유지되면 잠근다. 근거: 측면 세션 6개에서 측면 판정이 0.5초 연속 유지된 첫 시각이 3.8~12.9초이고 첫 반복 시작은 14.7~24.1초다(여유 7.0~12.8초).
- **해제**: 잠겨 있고 **STANDING 중** 비측면 판정이 **0.4초(약 7프레임) 연속**이면 해제한다. 근거: 측면 세션 6개의 운동 구간에서 비측면이 이어진 최대 길이는 **3프레임**(세션 9의 1건, 0.12초)이고 나머지 5개 세션은 0건이다. 세션 0에서 실제 돌아선 구간은 12프레임(0.67초), 40프레임(2.35초)이다. 해제선(7프레임)은 정상 최대(3)와 돌아섬 최소(12) 사이이며 양쪽에 4~5프레임(0.25~0.3초)의 여유가 있다.
  - 세션 0의 다른 비측면 구간 중 9프레임짜리(자리 잡기 4.1~4.5초, 재진입 46.6~47.1초)는 아직 잠그기 전이거나 잠금 획득 직후여서 해제 기준과는 관계없다.
- **반복 중(STANDING이 아닌 상태)**: 시점·다리·방향을 고정하고 시점 변화로 해제하지 않는다(기존 설계: 반복 중 고정). Pose를 놓쳐 2초 지나면 해제하는 것은 유지.
- **다리·방향은 측면으로 판정된 프레임에서만 갱신**한다. 비측면 프레임의 facing/leg는 버린다(정면에서 방향이 뒤집히는 문제 방지).
- **해제된 뒤**: 품질 판정과 점수는 하지 않고 안내 문구만 표시한다(기존 3-3). 반복 카운트를 계속할지는 별도 결정(7장의 ML 2차 방어선과 연결).
- 한계: 해제선은 세션 0의 돌아섬 2건과 측면 6세션 기준이다. 느리게 돌아서는 경우나 카메라 앞을 가로지르는 경우는 데이터가 없다.

## 10. 사용자 확인이 필요한 사항

1. **세션 9의 횟수**: 로그는 6회. 5회가 맞는지 확인(4장). 기준선(v0.1.x 0회)에는 영향이 없지만 "실제 횟수" 열에 들어간다.
2. **heel**: 점수에서 제외·참고 표시로 둘지, 뒤꿈치를 크게 든 세션을 재측정할지(5장).
3. **depth 교정선 95°, torso_shin 교정선 35°**: 데이터는 의도한 오류가 한 수준뿐이어서 교정선은 가정이다. 정상/주의 경계(80°, 25°)는 데이터 틈에 근거한다.
4. **depth와 torso_shin의 연동**: 얕은 스쿼트가 torso_shin도 주의로 만든다(5/8회). 이중 감점을 허용할지.
5. **ML**: `jump`를 목록에서 빼고 Y = 0.40으로 둘지(7장).
6. **비스쿼트 기하 조건**: 최소 길이 1.0초, 엉덩이 하강량 0.25, (측면에서) 양발 간격 ≤ 0.25 L, 몸통 ≥ 30°를 Phase 2의 반복 확정 조건에 넣을지(6장).
7. **BodyLock 획득 0.5초 연속 / 해제 0.4초 연속**(9장).
8. 이동 구간 규칙(짧거나 끊긴 후보가 core 밖이면 제외)의 형태를 그대로 쓸지.

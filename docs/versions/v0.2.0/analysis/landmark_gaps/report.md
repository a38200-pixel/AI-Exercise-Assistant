# 랜드마크 공백 원인 분석 (분석만, 구현 없음)

사람(YOLO)은 대부분 찾는데 landmark가 없는 프레임이 로그마다 12~25%다. 앞선 수정은 이 공백을 **견디게** 한 것이고 원인은 그대로다. 이 문서는 공백이 어디에 몰리는지 본다.
분석 대상: 로그 16개(field_test_1 13개, 2026-10-19 연속 세트 2개, 실시간 확인 `live_check_after_fix` 1개), 프레임 18,417개. `python -m scripts.analysis.landmark_gap_analysis`.

## 1. 현재 PoseLandmarker 설정 (`src/pose_estimator.py`, `config/settings.py`)
| 항목 | 값 |
|---|---|
| 실행 모드 | **IMAGE** (프레임마다 독립 추론, 추적 없음) |
| 모델 | `pose_landmarker_full.task` |
| `num_poses` | 1 |
| `min_pose_detection_confidence` | 0.20 (MediaPipe 기본 0.5) |
| `min_pose_presence_confidence` | 0.20 (기본 0.5) |
| `min_tracking_confidence` | 지정 안 함(기본값, IMAGE 모드에서는 쓰이지 않음) |
| 입력 | YOLO bbox + `BBOX_PADDING = 0.30`을 프레임 안으로 자른 crop을 **프레임마다** 넣음 |

## 2. 결과 요약
**공백은 거의 전부 "사람이 프레임 가장자리에 걸린 프레임"에서 생긴다.** 세트 안에서는 0~4%이고 세트 밖(자리 잡기, 걸어 들어오기, 끝나고 나가기)에서 20~70%다.

1. **세트 안 vs 밖**: 세트 안(확정 반복의 첫 시작~마지막 끝) 공백률은 로그 대부분 0.0~3.6%(예외: 첫 시험 세션 20.8%), 세트 밖은 11.6~71.3%. 세트 안 프레임 6,750개 중 YOLO는 찾았는데 landmark가 없는 프레임은 239개(3.6%).
2. **자세와는 약하게만 관련**: 세트 안 공백률은 서 있음 4.5%, 하강 2.2%, 최저점 부근 4.3%, 상승 3.6%로 **자세별 차이가 작다**. 무릎각 구간(≥160° 4.9%, 100~160° 4.9%, <100° 1.4%)도 같다. 전체(세트 밖 포함)로 보면 최저점 부근이 35%로 높지만 이는 세트 밖에서 몸을 숙인 채 가장자리에 있는 프레임이 섞인 결과다(교란).
3. **프레임 가장자리 접촉이 지배적**: 
   - crop이 프레임에 **전혀 안 잘린** 프레임의 공백률은 **0.1%**(전체)/0.0%(세트 안). crop이 좌우로 잘리면 76%, 아래(발 쪽)가 잘리면 27%, bbox가 발 쪽 경계에 닿으면 62.5%.
   - bbox가 위(머리)에 닿는 것만으로는 5.7%(발 아래 여유 60px 이상). **발 아래 여유가 20px 이하일 때 59~73%**.
   - bbox 높이가 프레임의 95% 이상이면 공백률 64.9%(세트 안은 해당 프레임이 217개뿐이지만 71%).
4. **bbox 변화량은 원인이 아니다**: 직전 프레임 대비 bbox 높이 변화와 공백 사이에 일관된 관계가 없다(<2% 변화 21.3%, 2~10% 3~5%, ≥10%는 133개뿐이고 30.8%). 빠른 움직임이나 크기 변화가 공백을 만든다는 근거는 없다. 종횡비 h/w 2.0 미만(옆으로 넓은 bbox, 가장자리에서 팔다리가 잘리거나 걷는 중)에서 43%로 높고 2.0 이상은 5~7%.
5. **YOLO 신뢰도**: 신뢰도가 낮을수록 공백이 많다(0.5 미만 74%, 0.85 이상 12.7%). 가장자리·잘린 몸과 교란되어 독립된 원인으로 볼 수 없다.
6. **연속성**: 직전 프레임이 공백이면 다음 프레임도 공백일 확률이 79.9%. 공백은 한두 프레임이 아니라 덩어리로 온다.
7. **공백 길이 분포**(연속으로 landmark가 없는 구간): 

| 구분 | 구간 수 | 중앙값 | p90 | p99 | 최대 | >0.5초 | >1.0초 | >1.5초 |
|---|---|---|---|---|---|---|---|---|
| 세트 안 | 80 | 0.09s | 0.26s | 1.29s | 2.18s | 4 | 2 | 1 |
| 세트 밖 | 697 | 0.11s | 0.45s | 1.68s | 25.40s | 58 | 21 | 10 |

   세트 안의 공백 80개 중 79개가 1.5초 이하라 이번 수정(`REP_STANDING_MAX_GAP_SECONDS` 1.5초)으로 대부분 견딘다. 1.5초를 넘는 1개(2.18초)는 초기화된다. 세트 밖의 긴 공백(최대 25초)은 사람이 화면을 벗어난 구간이다.

### 해석
- 공백의 주원인은 **모델 설정이 아니라 촬영 구도**다. 발끝이나 몸 옆이 프레임 가장자리에 닿아 crop이 프레임에서 잘리면(발 쪽 여유 20px 이하, 좌우 잘림) PoseLandmarker가 포즈를 못 찾는다. crop이 안 잘리는 구도에서는 0.1%다. 이미 앱은 "발끝까지 화면에 들어오게" 안내(전신 무효 사유)를 하지만, **landmark가 없는 경우(`present`가 False)는 전신 무효 안내와 다른 경로**라 안내가 안 뜰 수 있다(RepTracker의 안내 사유는 landmark가 있는 프레임의 `body_valid`/`side_now`로 정한다).
- 세트 안 공백(3.6%)도 거의 모두(239개 중 237개) bbox가 프레임 경계에 닿은 프레임이다. 즉 세트 중간의 공백도 구도(발 쪽 여유)로 줄일 수 있다.

## 3. 실행 모드·설정을 바꿨을 때 기대 효과와 위험 (제안만)
| 변경 | 기대 효과 | 위험 | 로그 재생으로 검증 가능? |
|---|---|---|---|
| **A. 구도 안내 강화**(landmark가 없는 채 bbox가 프레임 발 쪽/좌우 경계에 닿은 상태가 오래 가면 "뒤로 물러서 발끝이 화면에 들어오게" 안내) | 가장 큰 효과 기대(공백의 지배 원인이 구도). 모델·속도 영향 없음 | 안내 문구 추가뿐 | **가능**(로그의 bbox·공백으로 안내가 언제 떴을지 재생) |
| **B. 가장자리 여유 만들기: crop을 프레임 밖까지 검은색으로 패딩**(letterbox)해 넣기 | crop이 잘려 몸이 이미지 가장자리에 붙는 상태를 피해 검출이 잘 될 수 있음(잘리지 않은 crop의 공백률 0.1%라는 관측과 일치) | 패딩된 이미지에서 landmark 좌표를 crop 좌표로 되돌리는 변환 필요(분류기 입력 좌표계가 바뀔 수 있음); 실제로 프레임 밖에 있는 발은 복원 못 함(전신 유효 검사는 계속 실패) | **불가**(추론 필요) |
| **C. 공백 프레임에서 한 번 재시도**(패딩을 키운 crop, 또는 전체 프레임) | 공백 때만 추가 추론이라 평균 시간 증가 작음(세트 안 3.6%) | 공백 프레임 처리 시간 2배; 재시도가 엉뚱한 사람을 잡을 수 있음 | **불가** |
| **D. `min_pose_detection/presence_confidence`를 0.20 → 0.10** | 이미 낮아 효과 불확실(공백이 임계값 미달인지, 검출 실패인지 API가 알려 주지 않음) | 잘못된 포즈 채택 증가 | **불가** |
| **E. 모델 `full` → `heavy`** | 가장자리·부분 가림에 더 강할 수 있음 | 추론 시간 증가(FPS 감소) → 공백보다 큰 문제 | **불가** |
| **F. 실행 모드 VIDEO/LIVE_STREAM** | 이전 프레임 추적으로 검출 단계를 줄여 안정/빠를 수 있음 | **프레임마다 crop이 달라지는 구조에서는 추적이 성립하지 않는다**(아래) | **불가** |

**VIDEO 모드에 대한 의견(권장하지 않음)**: VIDEO/LIVE_STREAM 모드의 추적은 직전 프레임의 landmark로 다음 프레임의 관심 영역(ROI)을 잡는다. 지금은 매 프레임 YOLO bbox로 crop을 새로 만들어 넣으므로 같은 이미지 좌표계가 유지되지 않는다(crop의 원점과 크기가 프레임마다 바뀌고 가장자리에서는 잘림이 달라진다). 직전 landmark가 가리키는 ROI가 새 crop에서는 다른 위치가 되어 추적이 틀어지거나, 신뢰도가 낮아 매번 재검출로 돌아가 IMAGE 모드와 같아진다. 쓰려면 **전체 프레임을 넣고** landmark를 YOLO bbox 기준 crop 좌표로 변환하는 구조 변경이 필요하고, 그러면 분류기(XGBoost) 입력 좌표계와 다중 인물 처리가 바뀌므로 별도 설계·재검증이 필요하다. 또 이번 분석상 공백의 원인이 추적이 아니라 구도이므로 기대 효과도 불확실하다.

## 4. 로그 재생으로 검증할 수 없는 것과 검증 방법
- 로그에는 영상이 없고 PoseLandmarker의 **실제 추론 결과를 바꿀 방법이 없으므로** B~F는 로그 재생으로 검증할 수 없다(로그는 "공백이었는가"만 알려 주고 다른 설정이었다면 공백이 아니었을지는 모른다). 공백이 임계값 미달인지 검출 실패인지도 로그로는 알 수 없다.
- **같은 카메라 입력을 두 설정으로 기록**하는 개발용 비교 도구를 제안한다(구현하지 않음): 프레임마다 YOLO를 한 번 돌리고 같은 crop을 설정 A(현재)와 B(변경안)로 각각 PoseLandmarker에 넣어, 영상은 저장하지 않고 프레임별로 `공백 여부`, landmark 차이(무릎각 등), 추론 시간만 JSONL로 남긴다. 사용자가 (1) 발끝이 충분히 들어오는 구도, (2) 발이 가장자리에 걸리는 구도에서 각각 1세트씩 한다. 비교 지표: 세트 안/밖 공백률, 둘 다 성공한 프레임에서 무릎각 차이의 분포(좌표계 변환이 분류·판정을 바꾸지 않는지), 평균·p95 추론 시간.
- 먼저 할 일(로그로 가능): A(구도 안내) 효과를 로그 재생으로 추정하고, 2차 실측 프로토콜의 카메라 배치 지침에 "발 아래 프레임 여유"를 수치로 넣는다(예: 발 아래 20px 이상).

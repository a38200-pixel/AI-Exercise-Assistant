# 가설 5 사전 검증 (합성): 평활이 연속 반복의 봉우리를 160° 아래로 깎는가

가설 5: 휴지 없는 연속 스쿼트에서는 무릎각 봉우리가 짧게 스치기 때문에, 반복 경계가 쓰는 One Euro 평활값이 봉우리 최대값을 깎아
STANDING 복귀 기준(160°)에 못 닿게 만들어 반복이 합쳐진다. 카메라·실측 로그 없이 합성 신호로만 확인했다.

## 방법
- 무릎각 = 코사인 파형(봉우리 162·165·170°, 바닥 85°), 휴지 없음, 연속 10회. 반복 1회 주기 2.5 s(느린 연속) / 2.0 s(보통) / 1.5 s(빠르게).
- FPS 8·15·30, 샘플 위상 2종(정점 위에 샘플이 떨어짐 / 정점 사이에 떨어짐 = 최악). 처음·끝 봉우리는 잘려 있어 뺐다.
- 평활: 제품과 같은 `OneEuroFilter`(현재 설정 min_cutoff 1.0, beta 0.02, d_cutoff 1.0)를 그대로 사용.
- "각도만으로 센 반복": 160°/150° 히스테리시스만 적용한 반복 수(엉덩이·길이 등 확정 조건은 제외).
- 재생: `python -m scripts.analysis.hypothesis5_synthetic --markdown`

## 해석
- **깎임 크기**: 평활은 봉우리를 FPS 30에서 0.5~0.8°, 15에서 0.9~1.7°, 8에서 1.6~2.7° 깎는다. 주기가 짧을수록(빠를수록), FPS가 낮을수록 더 깎인다.
- **160°에 못 미치는 조건은 1개뿐이다**: 봉우리 162° · FPS 8 · 주기 1.5 s(평활 봉우리 159.3°, 10회 중 0회 인식). 같은 162°라도 FPS 15에서는 160.4°로 닿는다.
  FPS 8·주기 2.0 s에서도 162°가 160.0°로 경계에 걸린다(이 표는 소수 첫째 자리 반올림이며 160 이상으로 통과).
- **165° 이상은 모든 조건에서 통과**한다(최악 162.3°).
- 실측 로그의 처리 속도는 중앙값 약 17 FPS(세션 1~9, 간격 p95 0.065 s)였다. 이 조건이면 깎임은 대략 1.0~1.5°라, **평활 하나만으로는 봉우리가
  162° 이하로 낮을 때만 문제**가 된다.

## 결론
가설 5 단독으로 라이브 테스트의 누락을 설명하려면, 사용자의 원본 봉우리가 160~162° 안팎이어야 한다. 그보다 낮으면(예: 158°) 평활과 무관하게 원본이
이미 160°에 못 닿는 것이라 가설 1(복귀 각도)이 원인이다. 어느 쪽인지는 재현 로그의 `knee`(원본)와 `knee_smoothed`의 반복 사이 최대값을 나란히 보면 가려진다.
대응안 플래그 `REP_BOUNDARY_SIGNAL=light|raw`가 이 경우를 다룬다(기본 꺼짐).

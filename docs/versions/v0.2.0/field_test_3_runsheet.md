# 3차 실측 진행표 (실측 당일용, 한 장)

이유와 판정 규칙은 `field_test_2_protocol.md` 11절(11.1 결론 규칙 포함). 이 문서는 **당일 보고 따라 하기만** 하면 되게 줄였다. 카메라는 사람이 직접 켠다.
참가자 코드는 **`P02`** 로 적었다.
- **새 참여자(본인·P01이 아닌 사람)**: 코드를 P02로 쓴다(두 번째 새 사람이면 P03). 이 문서의 `P02_`는 그대로 쓴다.
- **P01의 다른 날**: 코드를 `P01D2`로 쓴다. 이 문서의 `P02_`를 전부 `P01D2_`로 바꾼다(편집기 전체 바꾸기). 이 경우 합격해도 "같은 사람의 다른 날 재현"으로만 기록된다(11.1).

> **이번 실측은 3차 확인이다.** 2차 뒤에 바꾼 값(ML 라벨 조건 제거, 최저점 발 간격 ≤ 0.40, 반복 중 엉덩이 이동 ≤ 0.70)을 확인한다. **실측 중에는 설정·값·코드를 고치지 않는다.** 합격 기준(`field_test_2_protocol.md` 10절)과 결론 규칙(11.1절, 2026-10-20 결정)은 결과를 보고 바꾸지 않는다. 안 맞아도 **고치려 하지 말고 그대로 기록**한다. **코드 변경은 3차 확인이 끝날 때까지 하지 않는다.**

## 0. 한눈에
| 구분 | 세션 | 예상 시간(한 사람) |
|---|---|---|
| 준비 | 아래 1절 | 약 8분 |
| **필수 10개** | 진행 1~10 | 약 28분 (세션당 약 2.5분 + 연속 10회 뒤 추가 휴식 2분 + 런지·자리 뜨는 동작 설명 시간) |
| 선택 3개 | 진행 B1~B3 | 약 8분 |

- 예상 시간의 근거: 1차 실측은 13개 세션을 33분에 했다(세션당 약 2.5분: 실행, 동작, 종료·입력, 확인, 휴식 포함). 이번에는 동작 설명이 필요한 세션(진행 7~10)이 있어 조금 더 걸린다.
- **필수만 하면 준비 포함 약 36분**이다(선택까지 하면 약 44분). 선택은 **필수 10번 뒤**에 한다.
- **3차 판정은 필수 세션으로 한다.** 시간이 모자라면 선택을 건너뛴다.

## 1. 준비 체크리스트 (실행 전)
- [ ] **코드 동결 확인** (이 진행표가 기준으로 삼은 코드): 아래 출력이 모두 기대와 같아야 한다. 다르면 **실측하지 말고** 사용자에게 알린다.
  - `git branch --show-current` → `feature/v0.2.0-squat-quality`
  - `git log -1 --format=%h -- src config` → **`8b749f1`** (마지막으로 `src`·`config`를 바꾼 커밋. 이 값이 다르면 코드가 바뀐 것이다)
  - `git diff --stat 3e95593 HEAD -- src config tests scripts` → **출력 없음** (기준 커밋 `3e95593`은 이 진행표 바로 앞 커밋이며, 그 뒤로는 문서만 바뀌었어야 한다)
  - `git status`가 깨끗해야 한다. `git rev-parse --short HEAD`를 **기록표 머리말에 적는다**(이 진행표가 들어간 커밋 또는 그 뒤의 문서 커밋).
- [ ] **테스트가 그대로 통과하는지**(카메라 없음, 1분): `python -m pytest tests -q` → **650 passed**.
- [ ] **GPU**: `nvidia-smi` — 학습 같은 다른 GPU 프로세스가 없는지 본다(있으면 끈다. FPS가 달라진다).
- [ ] **설정이 기대값인지**: 
  ```
  python -c "import config.settings as s; print(s.USE_REP_TRACKER, s.REP_SET_BASELINE_ENABLED, s.REP_RETURN_KNEE_ANGLE, s.REP_BOUNDARY_SIGNAL, s.BODY_LOCK_RELEASE_GRACE_SECONDS, s.REP_OTHER_EXERCISE_MAX_RATIO, s.REP_MAX_ANKLE_GAP_BOTTOM, s.REP_MAX_HIP_SHIFT)"
  ```
  → **`True False None smoothed 0.0 None 0.4 0.7`** 이어야 한다.
- [ ] **다른 무거운 프로그램 종료**, 노트북이면 전원 연결.
- [ ] **카메라 위치는 2차 실측과 같게**(가능하면). 거리 기준(영상 창을 보며 맞춘다):
  - 발끝 아래로 **화면 높이의 4% 이상 여유**(480p에서 약 20px, 발 아래 빈 바닥이 손바닥 폭 정도 보임).
  - 몸(머리~발) 높이가 **화면 높이의 60~80%**.
  - 좌우 가장자리에 닿지 않게 **화면 가운데**.
  - "뒤로 물러서 주세요" / "화면 가운데로 이동해 주세요"가 **뜨지 않는 자리**여야 한다(1.5초 넘게 서 있어 보기).
- [ ] **바닥 위치 표시**(테이프): **정위치**(위 기준을 맞춘 발 위치 두 점). 이번에는 가까운 자리 표시가 필요 없다. 진행 9, 10번은 **정위치에서 시작해 걸어 나갔다가 정위치로 돌아온다**.
  - 카메라 높이와 위치는 한 번 정하면 **실측이 끝날 때까지 건드리지 않는다**. 기록표 머리말에 카메라 거리(발에서 카메라까지)와 높이를 적는다.
- [ ] **영상 창에서 `R`, `S`, `E` 키를 누르지 않는다.** (`R`·`S`는 화면 카운트를 0으로 되돌린다. `E`는 운동 세션을 끝낸다.) 모드 키 `0`, `1`, `2`도 누르지 않는다. 종료는 `Q` 또는 `ESC`. **실수로 눌렀으면 그 세션을 버리지 말고 기록표 특이사항에 "R 눌림" 등으로 적는다.** 키 입력은 로그에 남고(`event kind=key`), 3차 A 판정이 그 로그로 이루어진다.

- [ ] 보조자가 있으면 종이/계수기를 주고, **화면을 보지 말고 몸 동작만** 세게 한다.

## 2. 세션표 — 필수 (이 순서대로)
공통 순서: **① 명령 실행 → ② 정위치에서 측면(해당 시점)으로 서서 0.5초 이상 가만히 → ③ 동작 → ④ 동작 후 가만히 1~2초 → ⑤ `Q`/`ESC` → ⑥ 터미널에서 "실제 반복 횟수" 입력 → ⑦ 3절 확인 → ⑧ 쉬기(1분 이상).**
"휴지 있음" = 올라와서 서서 1~2초 쉬고 다음 반복. **스쿼트가 아닌 동작(진행 6~10)의 "실제 횟수"는 스쿼트로 한 횟수(0 또는 세션 안의 스쿼트 수)** 이고, 한 동작의 횟수는 특이사항에 적는다.

> **연속 세트(진행 5)**: 시작 자세로 0.5초 이상 선 다음, 올라온 곳에서 **쉬지 말고 곧바로 다음 반복**을 한다. 속도는 평소대로 한다. **실제 속도와 서 있는 시간은 끝난 뒤 로그에서 잰다**(서 있는 시간 중앙값이 0.5초 미만이어야 "위에서 멈추지 않은" 연속으로 인정, 3절). 참고값: 2차 P01 연속 세트의 서 있는 시간 중앙값은 0.29초였다(유효). 힘들면 중간에 멈추지 말고 그 시점까지 한 횟수를 실제 횟수로 입력한다.
> **런지 두 형태(진행 7, 8)**: 2차에서 스쿼트로 세어진 런지는 **발을 모으고 있다가 내딛는** 형태(7)였고, 1차에서는 **한 걸음 내딛은 채 서 있는** 형태(8)였다. 두 형태를 모두 해야 둘 다 확인된다. 편한 범위에서만 한다.
> **진행 9, 10**: 다른 사람이 지나가지 않게 하고, 걸어 나가는 방향은 카메라 시야 **옆**(왼쪽 또는 오른쪽)으로 한다. 시야 밖으로 나갔다가 돌아올 때 천천히 걷는다.

## 3. 세션 하나 끝날 때마다 확인 (3가지)
1. **파일 생성**: 터미널에 `[Sequence] Saved: data/landmark_sequences/session_<시각>_<자세>_<시점>.jsonl`이 떴는지. 파일 이름을 기록표에 적는다.
2. **footer 입력**: 종료 직후 `실제 반복 횟수`를 입력했는지(Enter로 건너뛰면 "미입력"이 된다). 놓쳤다면 기록표에 적어 두고 나중에 보조자 기록으로 채운다.
3. **그래프로 actual / screen / detected**(쉬는 동안 실행, 10~20초):

   PowerShell:
   ```
   python scripts/analysis/plot_landmark_sequence.py --session (Get-ChildItem data\landmark_sequences\*.jsonl | Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName
   ```
   다른 셸이면 터미널에 찍힌 `Saved:` 경로를 복사해 `--session` 뒤에 붙여넣는다. 출력의 **`counts : actual N | screen N | detected N`** 한 줄을 기록표에 옮긴다.
   - actual = 입력한 실제 횟수, screen = 화면에 센 횟수, detected = 로그에서 확정된 반복. 보통 screen = detected.
   - 출력 아래쪽 `rep_end` 줄에 후보마다 `COUNTED` 또는 `REJECTED(사유)`가 나온다. **진행 6~10에서 `REJECTED(feet_apart_bottom)`, `REJECTED(hip_shift)` 같은 사유가 보이면 새 조건이 일한 것**이므로 특이사항에 적는다. `COUNTED`가 보이면 **어떤 동작 때였는지**(몇 초쯤)를 적는다.
   - `events : {...}` 줄의 `key` 개수는 키 입력 수다. **`Q`/`ESC`로 끝낸 정상 세션은 `key`가 1개(quit)** 다. 2개 이상이면 다른 키가 눌린 것이니 특이사항에 적는다. 어떤 키였는지는 아래로 본다.
     ```
     Select-String -Path (Get-ChildItem data\landmark_sequences\*.jsonl | Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName -Pattern '"kind":\s*"key"' | ForEach-Object { $_.Line }
     ```
   - 기대는 2절 표의 마지막 열이다. 안 맞으면 **고치려 하지 말고 그대로 기록**하고 특이사항에 적는다.
4. **(진행 5 연속 세트만) 서 있는 시간 확인**: 

   ```
   python -m scripts.analysis.continuous_set_analysis --log <그 로그 경로> --fixtures --fps 17 --dropout 0.3 --offsets 0.0
   ```
   출력의 **`서 있는 시간(반복 끝~다음 반복 시작): ... 중앙값 X초`**를 기록표 특이사항에 적는다. **0.5초 미만이면 유효**, 0.5초 이상이면 "멈추지 않은 연속"이 아니므로 **다시 한 세션 한다(최대 2번 더, 총 3번까지)**. 모든 시도의 로그를 파일 이름과 함께 기록해 둔다. **3번째에도 0.5초 이상이면 더 하지 말고** 그 3번째 로그로 판정한다("진짜 연속 조건 미달"로 기록, RELEASE.md 한계에 "위에서 멈추지 않는 연속 세트는 검증되지 않음" 추가).

## 6. 문제가 생기면
- **"뒤로 물러서 주세요" / "화면 가운데로 이동해 주세요"가 정위치에서 계속 뜬다**: 카메라를 더 멀리 두고 1절부터 다시. (진행 9, 10에서 걸어 나갈 때나 다가올 때 잠깐 뜨는 것은 정상이다.)
- **"카메라 쪽으로 옆모습이 보이게 서주세요" / "발끝까지 화면에 들어오게 서주세요"**가 2초 넘게 뜬다: 몸 방향·발끝을 고치고 다시 시작. 특이사항에 적는다. (선택 B1, B2는 정상이다.)
- **실수로 `R`/`S`/`E`/`0`/`1`/`2`를 눌렀다**: 세션을 버리지 말고 **기록표 특이사항에 적는다**(어느 동작 때, 어떤 키). 키 입력은 로그에 남는다. 화면 카운트가 0으로 돌아갔다면 그 뒤 화면 숫자는 신뢰하지 않고 `detected`(로그 확정 반복)로 센다. `E`를 눌렀다면 세션이 끝난 것이므로 그 세션은 다시 한다.
- **입력을 놓치고 창을 닫았다**: 기록표에 실제 횟수를 적어 두면 된다(로그는 "미입력").
- **세션 중간에 실제 횟수가 헷갈린다**: 보조자 기록과 다르면 둘 다 기록표에 적는다("정답 불확실"로 분석에서 제외).
- **진행 9, 10에서 사람이 시야 밖으로 나가 있는 시간이 길다**: 괜찮다(사람 없음 프레임). 로그는 정상이다.

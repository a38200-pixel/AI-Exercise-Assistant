# Phase 5(릴리스) 체크리스트

릴리스 전에 확인할 것을 모은 목록이다. DEVLOG에 흩어져 있던 항목을 모았고, 완료하면 체크한다. (이 문서는 2026-10-19에 만들었고 2026-10-20에 2차·3차 실측과 본인 연속 세트 확인 결과에 맞게 갱신했다.)

**현재 상태(2026-10-20)**: 실측은 끝났다(이후 다른 참여자의 실측은 하지 않는다). 남은 실측성 작업은 **본인 연속 세트(B) 재실시**뿐이다. 코드는 그 확인이 끝날 때까지 동결(`src`·`config` 마지막 커밋 8b749f1)이다. Phase 5로 진행하는 것은 3차 결과를 본 뒤의 사용자 결정(규칙 예외, 프로토콜 11.2절)이다.

## 실측·판정 결과 정리
- [x] **2차 실측(P01) 판정 완료**: A, B, C(런지), G 불합격 → ML 라벨 조건 제거, 최저점 발 간격, 엉덩이 이동 조건 적용(커밋 4ba35f4), 3차에서 재확인. 2차 A(세션 4, 확정 6 / 화면 5)는 **판정 보류**로 남는다(키 로그 없음, 첫 반복 뒤 S로 리셋됐을 가능성이 높음). 보류를 풀 방법은 없다.
- [x] **3차 실측(새 참여자 P02) 판정 완료**: A, C, F, I 합격 / E(0/15), G(0/5) 불합격 / B 판정 보류(서 있는 시간 0.87초). 원인은 참여자가 대상 동작을 수행하지 않은 것으로 보이며 영상이 없어 독립 확인은 불가. **규칙 예외 결정**(값 변경 없이 Phase 5 진행, 프로토콜 11.2절).
- [ ] **연속 세트(B) 본인 재확인**(`field_test_3_self_continuous.md`): 시도 1은 10/10 정확하지만 **서 있는 시간 중앙값 1.01초(0.72~1.10)로 유효 조건(0.5초 미만) 미충족**이라 B 판정 불가. 시도 2, 3(총 3회까지)을 한다. 같은 사람의 새 데이터이며 일반화 증거가 아니다.
- [ ] 위 결과에 따라 **RELEASE.md 연속 세트 문구를 확정**(진행표 4절 표: 유효·합격 / 3번 모두 유효 조건 미달 / 유효·불합격이면 원인 분석 후 사용자 결정). 지금 문구는 잠정이다.
- [ ] **서버 업로드 확인 결과 기록**: 사용자가 Supabase에서 P01 9건, P02 10건(`analysis/cloud_upload_check.md` 3.1, 3.2)을 확인·삭제하고, 본인 세션(1차 13건 + 실시간 확인 4건)은 삭제 여부를 정해 결과를 DEVLOG에 적는다. 본인 확인(시도 1)은 S·E를 누르지 않아 업로드가 없다.
- [x] RELEASE.md 5절 한계에 검증 범위 갱신(카운트는 세 사람, 자세 판정은 값을 정한 두 사람, 엉덩이 이동 조건 작동 사례 1건).

## 코드·설정 (연속 세트 확인이 끝나 코드 동결이 풀린 뒤)
- [ ] **기본 꺼짐 플래그 4개(세트 단위 기준 `REP_SET_BASELINE_ENABLED`, 복귀 각도 `REP_RETURN_KNEE_ANGLE`, 경계 신호 `REP_BOUNDARY_SIGNAL`, 잠금 유예 `BODY_LOCK_RELEASE_GRACE_SECONDS`)를 0.2.0에서 제거할지 유지할지 결정.** 판단 자료: 버그 수정 뒤 연속 세트는 플래그 없이 모두 정확했다(c10 10/10, c10_fast 10/10, P01 10/10, P02 10/10, 본인 10/10). 세트 단위 기준과 복귀 각도는 켜면 1차 스트레치 런지가 세어지는 부작용이 있다(settings.py 주석, `tests/test_rep_flags.py`의 알려진 한계 테스트). 제거하면 관련 코드·테스트·`replay_flags` 프리셋을 함께 정리하고 전체 테스트를 다시 돌린다. 유지하면 RELEASE.md에 "켜지 않음, 검증되지 않음"을 적는다.
- [ ] 코드가 바뀌면 `tests/` 전체 재실행(현재 650개 통과)과 `replay_fidelity_check`(26개 로그 일치)를 다시 확인한다. 코드가 바뀌지 않으면 그대로 둔다.

## 설치판(패키징 빌드) 확인
- [ ] **설치판에서 운동 기록이 `%LOCALAPPDATA%\FitRoute\workout_logs\`에 저장되는지 확인**: 세션을 시작·종료한 뒤 `workout_<시작시각>.json`이 생기고(`schema_version` 1, 반복별 결과), 설치 폴더에는 아무것도 안 생기는지, 폴더가 읽기 전용일 때(또는 일부러 막았을 때) 세션 종료와 서버 업로드가 정상이고 콘솔·로그에 저장 실패 한 줄이 남는지 본다. 개발 실행은 `data/workout_logs/`.
- [ ] 실제 PyInstaller 빌드를 만들어 `--diagnose-runtime`로 확인(지금까지는 spec·런처의 정적 확인만 했다).
- [ ] 빌드한 앱에서 안내·점수 문구가 한글로 나오는지(맑은 고딕 폰트 탐색, 없으면 영어 대체), `PIL.*` hiddenimports가 spec에 반영됐는지(기준 spec만 수정함, `optimized*.spec` 3개는 손대지 않음).
- [ ] 패키징 빌드에서 `--log-sequence`의 실제 횟수 입력(footer)이 묻지 않는지(frozen은 묻지 않음).
- [ ] 설치판 스모크(사용자 직접, 카메라 사용): 앱 시작, 측면 스쿼트 몇 회가 세어지는지, 점수 문구가 나오는지, 구도 안내가 한글인지, 종료 후 로컬 기록이 생기는지.
